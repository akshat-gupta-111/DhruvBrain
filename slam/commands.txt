================================================================================
  DHRUV SLAM — COMPLETE TERMINAL-BY-TERMINAL OPERATION GUIDE
  Hardware: NVIDIA Jetson Orin Nano | RPLidar A1 | ROS 2 Humble
================================================================================

SETUP: SSH into your Jetson from your Mac in 4 separate Terminal tabs.
  ssh dhruv@<YOUR_JETSON_IP>

NOTE: The ROS environment MUST be sourced in EVERY new docker exec shell.
      Every terminal below includes the full sourcing commands explicitly.

================================================================================
PHASE 1: BUILD AND START THE CONTAINER (ONE TIME SETUP)
================================================================================

  # 1. Go to your project folder on the Jetson
  cd ~/Desktop/DhruvBrain/slam

  # 2. Build the Docker image (takes ~10 min on first run, fast after)
  sudo docker build -f dockerfile -t dhruv-slam .

  # 3. Remove any old container if it exists
  sudo docker rm -f my_robot_app 2>/dev/null || true

  # 4. Start the interactive container
  sudo docker run -it \
    --name=my_robot_app \
    --privileged \
    --net=host \
    -v /dev:/dev \
    -v ~/:/root/ \
    jetson_robot_manager

  → Terminal 1 will show the Python menu. Keep it here.

================================================================================
TERMINAL 1 — Robot Manager (Interactive Menu)
================================================================================

  # Already running from Phase 1 above.
  # You will see this menu:
  #   1: start_mapping
  #   2: set_checkpoint
  #   3: save
  #   4: test_mapping
  #   5: exit

  TYPE: 1   (then press Enter to start mapping mode)

================================================================================
TERMINAL 2 — RPLidar A1 Sensor Node
================================================================================

  # SSH into Jetson, then enter the container
  sudo docker exec -it my_robot_app bash

  # Source ROS environment (REQUIRED in every new shell)
  source /opt/ros/humble/setup.bash
  source /workspace/rf2o_ws/install/setup.bash

  # Install ros2 tools if not yet in image (skip after rebuild)
  apt-get install -y ros-humble-ros2topic ros-humble-ros2node ros-humble-ros2run 2>/dev/null || true

  # Launch the RPLidar A1 node (publishes /scan topic at 10Hz)
  ros2 launch rplidar_ros rplidar_a1_launch.py

  → You should see: "RPLidar health status : OK" and scan frequency: 10.0 Hz

================================================================================
TERMINAL 3 — RF2O Laser Odometry (converts /scan → /odom)
================================================================================

  # SSH into Jetson, then enter the container
  sudo docker exec -it my_robot_app bash

  # Source ROS environment (REQUIRED in every new shell)
  source /opt/ros/humble/setup.bash
  source /workspace/rf2o_ws/install/setup.bash

  # First, publish the physical location of the LiDAR on the robot (1.6m high)
  # This links 'base_link' (robot center) to 'laser' (sensor)
  ros2 run tf2_ros static_transform_publisher 0 0 1.6 0 0 0 base_link laser &

  # Run the odometry node
  ros2 run rf2o_laser_odometry rf2o_laser_odometry_node --ros-args \
    -p laser_scan_topic:=/scan \
    -p odom_topic:=/odom \
    -p publish_tf:=true \
    -p base_frame_id:=base_link \
    -p odom_frame_id:=odom

  → Wait for Terminal 2 (LiDAR) to be running first!
  → You should see scan data flowing instead of "Waiting for laser_scans"

================================================================================
TERMINAL 4 — SLAM Toolbox (builds the map)
================================================================================

  # SSH into Jetson, then enter the container
  sudo docker exec -it my_robot_app bash

  # Source ROS environment (REQUIRED in every new shell)
  source /opt/ros/humble/setup.bash
  source /workspace/rf2o_ws/install/setup.bash

  # Launch the SLAM mapper (must use real time, not sim time)
  ros2 launch slam_toolbox online_async_launch.py use_sim_time:=false

  → You should see: "CeresSolver: Using SCHUR_JACOBI preconditioner"

================================================================================
TERMINAL 5 — DIAGNOSTICS (verify everything is connected)
================================================================================

  # SSH into Jetson, then enter the container
  sudo docker exec -it my_robot_app bash

  # Source ROS environment
  source /opt/ros/humble/setup.bash
  source /workspace/rf2o_ws/install/setup.bash

  # Check all active topics (you must see /scan, /odom, /map)
  ros2 topic list

  # Verify scan data is flowing at ~10Hz
  ros2 topic hz /scan

  # Verify odometry is publishing
  ros2 topic hz /odom

  # Verify SLAM map is publishing
  ros2 topic hz /map

================================================================================
PHASE 2: LIVE BROWSER MAP VIEW
================================================================================

  Open on your Mac browser:
    http://<YOUR_JETSON_IP>:8000

  → The map will be BLANK (404) until SLAM has enough data to publish /map.
  → Drive the robot around for 10-20 seconds and the map will appear!
  → It auto-refreshes every 2 seconds.

================================================================================
PHASE 3: RECORD CHECKPOINTS WHILE MAPPING
================================================================================

  Drive the robot to a location you want to save, then:

  [Terminal 1] → Type: 2  (set_checkpoint)
  Enter name: desk_area

  Repeat for other locations:
  [Terminal 1] → Type: 2
  Enter name: door_exit

  [Terminal 1] → Type: 2
  Enter name: charging_station

================================================================================
PHASE 4: SAVE THE MAP
================================================================================

  [Terminal 1] → Type: 3  (save)
  Enter prefix: apartment

  → This writes to your Jetson home folder (~/ which is mounted as /root/):
      /root/apartment_map.yaml
      /root/apartment_map.pgm
      /root/apartment_checkpoints.json

================================================================================
PHASE 5: SWITCH TO NAVIGATION MODE (autonomous point-to-point)
================================================================================

  Step 1: Stop SLAM in Terminal 4 → Press Ctrl+C
          (Keep Terminals 2 and 3 running! LiDAR and odometry must stay alive.)

  Step 2: In Terminal 4, start Nav2 navigation stack:
    sudo docker exec -it my_robot_app bash
    source /opt/ros/humble/setup.bash
    source /workspace/rf2o_ws/install/setup.bash
    ros2 launch nav2_bringup bringup_launch.py \
      map:=/root/apartment_map.yaml \
      use_sim_time:=false

  Step 3: [Terminal 1] → Type: 4  (test_mapping)
    Enter room map name: apartment
    Enter target checkpoint: desk_area

  → Nav2 will autonomously navigate to the saved checkpoint!
  → It uses the live LiDAR costmap to avoid unexpected obstacles.

================================================================================
STARTUP ORDER (CRITICAL — follow exactly):
  1. Terminal 2: LiDAR node   (must be first — others depend on /scan)
  2. Terminal 3: RF2O odom    (needs /scan to be live)
  3. Terminal 4: SLAM toolbox (needs /scan + /odom)
  4. Terminal 1: Menu → type 1
  5. Browser: open http://<IP>:8000
